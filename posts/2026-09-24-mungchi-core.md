> 초안입니다. 사실관계와 표현을 직접 확인해 주세요.

> **이 편의 자리** — 왜 만드는가 → 기획서 → **펫 로직** → 오버레이 창

**펫의 상태를 "1분마다 포만감 −1" 같은 타이머로 깎지 않았다.
저장하는 것은 마지막 식사 시각과 똥 목록 같은 사실뿐이고, 배고픔 단계와 냄새 단계는 읽을 때마다 현재 시각으로 계산한다.**
그렇게 한 이유는 하나다. 앱이 꺼져 있던 시간도 펫의 시간이어야 한다.
밥만 주고 퇴근하면 다음 날 아침에 똥이 놓여 있어야 한다.

타이머 방식이면 꺼져 있던 열네 시간을 켤 때 따로 따라잡아야 한다.
따라잡는 코드와 평소 코드가 두 벌이 되고, 둘이 어긋나는 날이 온다.
사실만 저장하면 한 벌이다. 구축기에서 원본을 남기고 집계는 나중에 만든 것과 같은 생각이다.

## 시각도 커서도 난수도 입력으로 받는다

펫 로직은 DOM도 Tauri도 모른다. 현재 시각, 커서 위치, 화면 크기, 난수 시드를 전부 입력으로 받고
화면 좌표로 된 "장면"을 내놓는다. 창이 몇 개인지, 어떤 OS인지는 모른다.
덕분에 네 시간 굶긴 펫이 브라우저 없이 테스트가 된다.

```ts
it('굶기면 커서까지 기어올라 매달린다. 머리는 커서 끝 아래에 있다', () => {
  const now = starveUntilHang(world, { cursor });
  const headY = world.pet.y - 96;
  expect(headY).toBeGreaterThanOrEqual(cursor.y);      // 커서 끝을 가리지 않는다
  expect(hitTest(scene(now), cursor)).toBeNull();      // 아래 앱의 클릭을 가로채지 않는다
});
```

기획서에 적은 규칙("매달려도 커서 끝은 가리지 않는다")이 그대로 단언문이 됐다.
시계를 뒤로 돌리면 경과 0으로 본다, 똥은 다섯 개까지만 남는다,
낮잠 도중에 껐다 켜면 남은 낮잠부터 이어 간다도 같은 식으로 고정했다.
지금 테스트는 34개다. 펫 로직 23, 캐릭터 팩 규격 8, 저장 3.

## 처음 실패한 셋은 로직이 아니라 내 어림이었다

첫 실행에서 23개 중 3개가 실패했다. 셋 다 같은 모양이었다.
"굶긴 뒤 60초를 더 돌리면 매달려 있을 것"이라고 적었는데 펫은 바닥에서 발을 구르고 있었다.

로직은 맞았다. 기본 수위 "보통"은 매달린 지 1분이 지나면 포기하고 내려온다.
내가 확인한 시점에는 이미 올라갔다가 포기한 뒤였다.
**테스트에 시간을 어림으로 적은 것이 잘못이었다.** "N초 뒤에 이 상태"를 "이 상태가 될 때까지 돌리고, 안 되면 실패"로 바꿨다.
숫자를 어림하지 말라는 걸 벤치에서만 지키고 테스트에서는 안 지킨 셈이다.

하나 더. 등반은 뒷모습인데, 처음 찍은 스프라이트는 주황색 덩어리였다.
얼굴이 없으니 자세가 안 읽혔다. 팔다리만 어두운 색으로 바꾸니 기어오르는 것처럼 보였다.
테스트는 "등반 프레임에 눈이 없다"까지만 말해 준다. 보이는지는 눈으로 봐야 했다.
그래서 같은 로직과 렌더러로 도는 브라우저 미리보기를 만들었고, [소개 페이지](https://xo0449.github.io/mungchi-site/)의 데모도 그것이다.

## 모르는 것

장면 객체를 프레임마다 새로 만든다. 30 FPS에서 문제가 되는지 재지 않았다.
지금 캐릭터 셋은 코드로 찍은 임시 그림이다. 한 마리에 필수 동작이 열세 개인데,
진짜 그림으로 한 마리를 끝내는 데 얼마나 걸리는지 모른다. 캐릭터를 파는 계획은 그 숫자에 달려 있다.
