> 초안입니다. 사실관계와 표현을 직접 확인해 주세요.

> **이 편의 자리** — 왜 만드는가 → 기획서 → 펫 로직 → 오버레이 창 → **Windows에 띄우기**

[4편](/posts/2026-09-25-mungchi-overlay/)에서 미룬 값이 얼마인지 모른다고 적었다. Windows 11 두 대(데스크톱 100%, 랩탑 125%)에서 띄워 보고 나서야 알았다.
**걱정하던 곳은 멀쩡했고, 생각도 안 한 곳에서 다섯 번 막혔다.**

## 된 것과 안 된 것이 예상과 반대였다

투명 창, 항상 위, 클릭 통과는 첫 실행에서 됐다. 펫 밖을 누르면 아래 앱이 클릭을 받았고,
커서가 펫 위로 올라간 뒤 창이 클릭을 받기 시작하기까지 두 번 재서 31ms, 27ms였다. 커서를 33ms마다 읽으니 그 정도가 맞다.

안 된 것은 이랬다.

| 겪은 장면 | 원인 |
|---|---|
| 작업표시줄에 펫의 버튼이 생겼다 | `skipTaskbar`를 켰는데도 창에 `WS_EX_APPWINDOW`가 남아 있었다 |
| 펫을 누른 뒤 치던 글자가 사라졌다 | 클릭이 오버레이를 전경 창으로 만들었다 |
| 우클릭 메뉴가 뜨는데 항목이 안 눌렸다 | 커서가 펫에서 메뉴로 옮겨가는 순간 클릭 통과가 다시 켜졌다 |
| 이름 칸에 친 글자가 뒤의 창에 찍혔다 | 포커스를 안 받게 해 둔 창은 글자도 못 받는다 |
| 외부 모니터를 꽂자 펫이 없어졌다 | 주 모니터에만 뜨게 해 뒀고, 꽂은 모니터가 주 모니터가 됐다 |

앞의 둘은 창 스타일을 고쳐서 풀었다. 그런데 Tauri가 쓰는 창 라이브러리(tao)는 클릭 통과를 켜고 끌 때마다 확장 스타일을 통째로 다시 쓴다.
한 번 걸어 둔 비트가 다음 클릭 통과 전환에서 지워졌다. 창을 서브클래싱해서 스타일이 바뀌려 할 때마다 다시 넣게 했다.

이름 칸은 원인이 둘이었다. 포커스를 풀어 주고 나니 한글만 들어가고 영문과 백스페이스가 안 먹었다.
`onkeydown = (e) => e.key === 'Enter' && ok()`가 Enter가 아닐 때 `false`를 돌려줬고, 속성으로 단 핸들러가 `false`를 돌려주면 그 키는 취소된다.
입력기가 따로 처리하는 한글 조합만 살아남은 것이다. 브라우저 미리보기에서도 있었을 버그인데 거기서는 못 잡았다.

설정 창은 오버레이 밖으로 뺐다. 상태와 설정 화면은 오버레이 안에 그린 DOM이었다. 써 본 사람의 말은 이랬다. 다른 창을 누르면 설정 창은 뒤로 가야 하고, 끌어서 옮길 수도 있어야 한다.
항상 위에 떠 있는 창 안에 그린 것은 둘 다 안 된다. 보통 창을 하나 더 만들고, 앱 본체는 오버레이에 둔 채 상태를 1초마다 보내 주게 했다.
모니터 문제는 설정에 "펫이 사는 모니터"를 넣어서 풀었다. 배율이 다른 모니터(125%와 100%) 사이를 켠 채로 옮겨도 창이 작업 영역에 맞았다.

## 설치 파일은 내 랩탑에서 만들 수 없었다

명령어 없이 exe 하나로 깔리게 하려고 설치 파일을 만들었다. 랩탑에서는 빌드가 안 됐다.
스마트 앱 컨트롤(서명 없는 새 실행 파일을 막는 Windows 11 기능)이 cargo가 빌드 도중에 만들어 돌리는 작은 exe를 막았다. 폴더를 바꾸면 다른 크레이트의 exe가 막혔다.
이 기능은 끄면 Windows를 초기화하기 전에는 다시 못 켠다. 끄지 않고 GitHub Actions의 Windows 러너에서 빌드했다. 캐시 없이 13분 45초 걸렸다.

여기서 하나를 더 알았다. **내 빌드를 막은 그 기능이 받는 사람의 PC에서는 설치 파일을 막을 수 있다.** 지금 올린 미리보기 버전은 서명이 없다.

## 모르는 것

- 이 앱의 간판인 "굶기면 커서에 매달린다"를 Windows에서 아직 못 봤다. 네 시간 넘게 굶겨야 하는데 그럴 틈이 없었다. 개발용 빌드에 시간을 건너뛰는 메뉴가 필요하다
- 릴리스 빌드의 CPU와 메모리. debug 빌드로 두 번 잰 값(워킹셋 약 400MB)밖에 없다
- 서명 없는 설치 파일이 스마트 앱 컨트롤이 켜진 PC에서 실제로 막히는지, 코드 서명에 얼마가 드는지
- macOS는 띄워 보지도 못했다

4편에서 "위험이 뒤로 간 것"이라고 썼다. 뒤로 간 값은 이틀에 걸친 실기였고, 대부분은 Win32 창 스타일과 포커스였다.
미리 스파이크를 했어도 이름 칸과 설정 창과 모니터는 못 찾았을 것이다. 셋 다 기능이 있어야 나오는 문제였다.
